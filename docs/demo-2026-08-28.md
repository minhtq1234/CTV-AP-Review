Goal: show the app and the reviewer workflow. Not a claim about accuracy — see **Don't say**.

## Start it

Two commands, in order, in one terminal. No credentials needed — the demo case is already
ingested, and IDP is only used at ingest time.

```
cd "/Users/lap16603/Documents/New project/work/CTV_APReview-stable/server"
python3 -m uvicorn app:app --host 127.0.0.1 --port 8002
```

```
cd "/Users/lap16603/Documents/New project/work/CTV_APReview-stable"
node_modules/.bin/vite --host 127.0.0.1 --port 5175 --strictPort
```

Then open **http://localhost:5175**.

Two gotchas that will bite otherwise:

- **The UI is hardcoded to port 8002** (`src/upload/api.ts`), and its CORS allows only
  5173–5175. Use exactly those ports.
- **Run ONE API server.** `CaseStore` caches its index in memory, so a second server on
  another port will not see cases the first one created, and vice versa. If a case is missing
  from the list, restart the API — that reloads from disk.

## The path

1. **Case list → open it.** The banner is the whole pipeline story in three lines:

       41 / 41 gói (tìm thấy / bảng kê) · 41/41 đã khớp tên · 0/41 đã xong
       36 gói được cắt lại sớm hơn 3 trang · 5 gói bị gộp đã tách ra
       CCCD: 39 đã gắn · 3 chưa ghép

   The second line is the splitter fix — boundaries were landing 3 pages late and 5 packets
   were merged into their neighbours. The third is IDP: the local reader attached 24 of 42
   cards, IDP attaches 39.

2. **`Tổng hợp` tab** — the five roster-level criteria. #20 reconciles the bảng kê's 41 rows
   against the Bảng Kê Thu Mua total, **240,305,556**, read twice (digits and Vietnamese
   number-words) and agreeing — that is the `digits-and-words-agree` in the payload.

3. **`Gói hồ sơ` → open packet 0.** Clean packet: 0 disagreements.

4. **Inside the packet, `25 tiêu chí`** — Acc's checklist, computed rather than typed. Click
   any mark to open the detail row: it shows what was read, from which document, and the note.
   Record a decision there — that is the override loop, and a confirmation counts toward
   `cần gửi lại` while the engine's own findings stay counted separately as candidates.

5. **`Xem chứng từ`** — the scan, with the field located. This is the point of the product:
   the tool marks the position, the reviewer validates by eye.

6. **Back out → `Xuất báo cáo gửi lại`** to close the loop.

## Don't say

- **Do not quote an accuracy figure.** 22 of the 41 packets carry at least one `no`. Eight
  packets were hand-checked and four of those `no`s were false; the other fourteen are
  unvalidated, so the true rate is unknown in both directions.
- **Do not present confidence as reliability.** It is `min(word confidence)` — how crisply the
  glyphs printed, not whether the right words were read. Measured: wrong reads at 93%, a
  correct read at 6%.
- **Do not claim IDP reads document fields.** It reads CCCD cards only. `doc_type=ID` is the
  only value the account accepts; a general document mode is an open question with GreenNode.

If asked about accuracy, the honest line is: extraction is good enough that the reviewer's job
is checking rather than typing, and we have just finished the first pass of measuring where it
is wrong — which found a class of false rejection now being fixed.

## Real data

The case contains real CTV names, CCCD numbers and bank accounts, and the scans are on screen

is in the room, say so before starting — there is currently no synthetic demo case.

## If something breaks

- **Case list empty or missing the demo case** → restart the API; the index is cached in memory.
- **"Can't reach backend"** → the UI is on a port outside 5173–5175, or the API is not on 8002.
- **A packet shows nothing in `Xem chứng từ`** → the page PNGs live in
  `server/data/cases/<id>/packets/<n>/`; the manifest's `src` paths are absolute from ingest
  time and may point elsewhere, but the viewer uses the API route, not those paths.
